Not another code review bot

AI is moving the software bottleneck below code review.

Coding agents make production cheaper. Trust gets harder. Review agents and scanners still read from the outside; they spend tokens and time rediscovering boundaries the program never made explicit.

The new question Not just: can the model write code?
Can the build make AI-written boundaries explicit before a human or LLM reviewer has to notice them?
A simple failure mode

The risky part can look completely normal.

An agent adds a file preview endpoint. The code compiles. The happy-path test passes. The bug is not syntax; the bug is that user input quietly became authority over the filesystem.

Ordinary code shape
fn preview_file(request):
    name = request.query["name"]
    path = "uploads/" + name
    return read_file(path)
The missing invariant
user input
  -> file path
  -> filesystem read

Was the name validated?
Can it escape uploads/?
Who checked that flow?

The dangerous fact is a dataflow: where the value came from, what it is allowed to become, and which effect it authorizes.

The obvious answers are useful, but downstream

The risk is not only that code needs more review.

  • LLM reviewers, scanners, and stricter prompts catch real bugs.
  • They do not change the substrate the agent wrote into.
  • If user input, secrets, SQL, paths, network, and filesystem effects are ordinary values, every later tool must infer the boundary from context.
  • Costly path: generate code, pay another model to inspect it, repair, re-review.
01

Prompt guardrails are instructions

They can be forgotten, contradicted, or routed around by a later edit. They are not part of the program.

02

Review agents are readers

They inspect a diff after the unsafe shape already exists, and they inherit the same ambiguity as the authoring model.

03

Scanners work from the outside

They are valuable, but they infer from code after it exists. The cheapest boundary is one the build can refuse by construction.

Shift left, below review

The cheaper control is the one the build can check.

  • Agents increase code volume and velocity faster than human review capacity scales.
  • Agentic review adds another paid inference pass over missing structure.
  • Compiler-visible boundaries move the check earlier: before review, before runtime, before rework.
01

Review becomes boundary inference

The hard question is no longer only what changed. It is whether an implicit security or authority boundary survived the change.

02

Tests catch examples late

Tests are necessary, but they mostly verify expected behavior. When they catch a boundary bug, the team is already paying rework cost.

03

LLM review still reads from the outside

A review model can scan more code than a human, but it spends tokens and runtime inferring provenance, authority, and effects from context.

What current languages leave implicit

Most languages express values. They do not express enough boundaries.

Python, TypeScript, Go, and similar languages can express types, modules, functions, and tests. They usually do not make these review questions part of the build artifact.

Where did this value come from?

User input, generated text, trusted config, local file, network response, secret-bearing environment, and database content often collapse into the same string type.

What is this code allowed to touch?

Filesystem, network, shell, database, credentials, logs, and imported dependencies are usually governed by convention and review, not compiler-visible grants.

The Heat thesis

Heat makes the boundary part of the program.

Explicit inputs
All arguments are named. Ambiguity is reduced because the model has fewer silent choices to get wrong.
Explicit errors
Errors are values. The compiler enforces handling instead of relying on hidden exception paths.
Explicit effects
Operations that touch the outside world are visible to the type system and review surface.
Explicit provenance
Values can carry where they came from, so risky flows can be refused before the program runs.
Compiler refusal
When the unsafe shape appears, the answer is not a warning or a style preference. The build stops until the boundary is explicit.
The shift

Better models help. They do not remove the need for enforceable boundaries.

The winning agentic-development stack will not be prompts alone. It will combine models with substrates that make the important properties visible: where data came from, which effects are allowed, what obligations remain, and whether the generated code actually discharged them.

Heat is built for that world: AI writes the code, humans review the intent, and the compiler refuses classes of mistakes that should not depend on somebody reading every line.
